# E0: перевірки ризиків — звіт

Дата: 2026-11-13. План: `studying-skills-frontend/design/editor-engine-2a.md`, розділ 6.
Усе міряно на цьому сервері в Linux-збірках Chromium, Firefox і WebKit (образ Playwright 1.65).
Windows, macOS і справжні клавіатури не перевірялися — це ручна перевірка (розділ «Що лишилося»).

## Підсумок

| № | Питання | Результат | Число |
|---|---|---|---|
| S1 | Ширини слів рушія й браузера збігаються | так, з умовою | окреме слово: найбільша різниця 0,14 px у всіх трьох браузерах (допуск 0,5) |
| S2 | Введення через прихований редактор працює | так в автоматичних тестах; ручна перевірка лишилась | 15 сценаріїв × 3 браузери зелені, 4 сценарії лише Chromium зелені |
| S3 | Формула однакова в DOM і PDF | частково | формули з контурів: до 0,75 pt різниці, у PDF вектор; кирилиця в `\text{}` — ні |
| S4 | wasm вантажиться в Next 16 | так | `next build` проходить, файл віддається як `application/wasm` з gzip, завантаження 65 мс локально |
| S5 | PDF з кирилицею, яку можна виділити | так | 1000 рядків: текст повертається; шрифти вбудовані підмножинами; wasm і нативна збірка дають однакові байти |
| S6 | Верстка вкладається в бюджет | так для прототипу | 125 тис. знаків (≈60 сторінок): повна верстка 155–260 мс у wasm, правка абзацу ≤ 1 мс |

Рішення: жоден запасний шлях не потрібен; план іде далі з трьома поправками нижче.

## S1. Геометрія (`spikes/s1-geometry`)

Що міряли: 1000 рядків (750 українських, 250 англійських), Liberation Serif Regular, 16 і 18,67 px,
щільність пікселів 1 / 1,25 / 1,5 / 2. Рушій — rustybuzz у wasm; браузер — той самий файл шрифту.

| Браузер | `text-rendering` | Слово окремо: p99 / найбільша, px | Рядок цілком: найбільша, px |
|---|---|---|---|
| Chromium | типове | 4,07 / 8,14 | 29,8 |
| Chromium | `geometricPrecision` | 0,07 / 0,14 | 1,77 |
| Firefox | будь-яке | 0,05 / 0,10 | 2,19 |
| WebKit | будь-яке | 0,07 / 0,14 | 1,77 |

Висновки:

- Chromium у Linux за замовчуванням округлює ширини гліфів до цілих пікселів. Сторінки мають
  малюватися з `text-rendering: geometricPrecision` — тоді розбіжності немає.
- Рядок, намальований одним шматком, розходиться з рушієм до 2 px (браузери інакше застосовують
  кернінг навколо пробілів). Тому малюємо **кожне слово окремим елементом** за координатою рушія,
  як і закладено в плані.
- Щільність пікселів на результат не впливає.
- Не перевірено: жирний і курсив, інші розміри, Windows і macOS.

## S2. Введення (`spikes/s2-input`)

Прототип: прозорий ProseMirror (`opacity: 0`, без подій миші) + окремо намальований шар з іншою
шириною; прихований редактор зсувається так, щоб його курсор збігався з намальованим.

Зелені в Chromium, Firefox і WebKit:

- український текст потрапляє в документ і на намальований шар;
- клацання по намальованому шару ставить курсор і не забирає фокус;
- курсор прихованого редактора збігається з намальованим (до 1,5 px) — це якір вікна складеного
  введення;
- виділення протягуванням, Shift+стрілки, заміна виділеного, скасування, Enter, Backspace;
- копіювання й вставлення; Ctrl+→, Home, End;
- прозорий редактор видно в дереві доступності як текстове поле з текстом документа.

Зелені лише в Chromium (в інших немає засобу автоматизації):

- складене введення через CDP: текст під час набору видно, підсумок потрапляє один раз;
- мертва клавіша;
- 300 швидких натискань без втрат і перестановок;
- емуляція Android: дотик ставить курсор, текст вставляється.

Знахідка: рідна стрілка, натиснута раніше ніж через ~50 мс після попередньої синхронізації
виділення, у Chromium і WebKit скасовується (ProseMirror повертає своє виділення). Власні команди
руху по стану документа працюють без затримок у всіх трьох браузерах. **Поправка до плану: рух ← →
і згортання виділення — наші команди, а не рідні** (E5, +1–2 дні).

## S3. Формули (`spikes/s3-math`)

30 формул, MathJax 3 → SVG. У PDF — через krilla-svg, растрових зображень у файлі немає.

- 28 формул складаються лише з контурів. Різниця меж чорнила між PDF і браузером: до 2 px при
  192 dpi (0,75 pt), у 24–27 з 28 — до 1 px. Умова: SVG вставлений у сторінку як елемент `<svg>`;
  через `<img>` WebKit зсуває частину формул до 4 px.
- 2 формули з кирилицею в `\text{}` (на зразок `v_{\text{сер}}`): MathJax лишає текст текстом і
  вгадує його ширину. У PDF літери зникли, у браузерах — інший шрифт і розріджені літери.
  **Поправка до плану: текст у формулах переводимо в контури шрифтом рушія й даємо MathJax
  справжні ширини** (E8, +2 дні).

Критерій плану (0,5 pt) формально не виконано: найбільша різниця 0,75 pt при точності вимірювання
0,375 pt.

## S4. wasm у Next 16

Окрема робоча копія фронтенда зі сторінкою, яка імпортує пакет `wasm-pack`. `next build`
проходить; файл потрапляє в `/_next/static/media/` з хешем у назві.

Розміри:

| Що | Байтів | gzip |
|---|---|---|
| формування гліфів + розрив рядків | 701 тис. | 273 тис. |
| PDF (krilla з растровими зображеннями й формуванням) | 2,08 млн | 785 тис. |
| Liberation Serif, одне накреслення | 370–394 тис. | не міряно |

Бюджет 1,5 МБ gzip на весь рушій досяжний; частину PDF варто вантажити окремо, коли натиснуто
«PDF».

## S5. PDF

krilla 0.8.2, 1000 рядків на 34 сторінках A4, три накреслення.

- `pdffonts`: три шрифти, усі вбудовані підмножинами, з таблицею Unicode.
- `pdftotext`: 692 рядки збігаються повністю, 307 — обрізані краєм сторінки (прототип не переносить
  рядки), 1 відрізняється пробілом біля невидимого знака.
- Нативна збірка: 130 мс. wasm у Chromium: 266 мс. Байти однакові.

## S6. Швидкодія

Прототип: абзаци, жадібний розрив рядків, кеш ширин відрізків; без таблиць, виносок і сторінок.

- Повна верстка 125 тис. знаків (1844 рядки): 155–260 мс у wasm.
- Повторна з кешем: 6–12 мс.
- Правка одного абзацу: p99 0,3–0,5 мс у Chromium (у Firefox і WebKit таймер кроком 1 мс).

Справжня верстка робить більше; числа — нижня межа, а не обіцянка.

## Що лишилося перевірити руками

1. Windows і macOS: ширини слів (сторінка `spikes/s1-geometry`).
2. Справжні клавіатури: українська розкладка, перемикання, мертві клавіші, вікно складеного
   введення біля курсора (сторінка `spikes/s2-input`).
3. Програма читання з екрана з прозорим редактором.

```
cd spikes/s1-geometry && wasm-pack build --release --target web && ../pw.sh s1-geometry node run.mjs
cd spikes/s2-input && npm i && npx esbuild main.js --bundle --outfile=bundle.js && ../pw.sh s2-input node test.mjs
cd spikes/s3-math && npm i && node gen.mjs && node layout.mjs inline && cargo run --release -- layout.json ../../assets/fonts/liberation/LiberationSerif-Regular.ttf out.pdf
cd spikes/s5-pdf && cargo run --release -- lines.txt ../../assets/fonts/liberation out.pdf && node wasm-check.mjs
```
